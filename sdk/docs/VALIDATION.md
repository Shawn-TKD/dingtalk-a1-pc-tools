## 本次发现并处理的问题

1. 旧Python接收器等回复时会丢弃不匹配的主动帧。SDK改为命令回复与事件分发分离；并发到达标记的测试已覆盖。
2. 简单地把每个Opus包都算20ms，会在真实异常开头包上算错时长。改为按TOC计算时间轴，并保留异常统计；完整解码核对实际时长。
3. 早期重构对stereo-coded包过于严格，导致原本可被Opus解码器输出为单声道的第9条备忘录被拒绝。移除了这条错误限制，改为保留原包并显式报告，不篡改声音数据。
4. 中途接入一段录音也可能收到stop。SDK现在要求观察到start才可报完整，避免把尾部片段自动发给Agent当作全量任务。
5. 初次安装因运行环境网络权限被拒而失败。获得下载权限后在同一虚拟环境正常安装；不是依赖不存在或代码构建失败。
6. 后续本地打包遇到全局pip缓存写入权限限制。改用`--no-cache-dir --no-index`本地构建，避免写旧全局缓存，不需要扩大SDK文件权限。

## 证据层级

`legacy_hardware_verified`：旧版本脚本/Android App或实验已实机通过，移植后的接口仍要复测。

`firmware_static_only`：处理函数和字段已从固件恢复，仅说明实现路径存在。返回200不代表执行成功。

`no_verified_external_command`：例如BLE任意震动，没有作为可用API提供。

本包不把测试数量换算成“产品完成百分比”。没有进行跨平台硬件兼容测试、数小时长连接续航测试、USB大于1GiB单文件测试或新版Wi-Fi吞吐测试。旧项目1GiB读写成功不能冒充这次重新测试成功。
