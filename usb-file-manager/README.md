# A1 文件空间

USB 本地文件管理界面。React + Vite 前端负责导航、中文目录、搜索、上传/下载状态；Python 后端使用此前验证的 HID 身份认证与 ADB SYNC 协议访问 A1。不是浏览器直接控制 USB，也不是标准 U 盘驱动。

## 使用

在本机 PowerShell 执行 `./start.ps1`。后台进程隐藏启动，浏览器会打开带本机访问凭据的完整链接。服务只监听 `127.0.0.1:8766`，不对局域网开放。

1. 用支持数据的 USB 线连接并唤醒 A1。
2. 点击“连接设备”，确认现在没有录音任务且允许中断 BLE。
3. “设备存储”浏览 `/emmc`；“录音目录”浏览 `/emmc/audio`。
4. “个人文件”对应 `/emmc/mindlink`，支持新建文件夹、单个或多个文件上传、拖放上传、下载。

访问令牌首次随机生成在 `.local/access-token.txt`，重启服务不会换链接。它与 A1 的 deviceSecret 完全独立。设备身份只从启动时指定的本机 JSON 读取，不发送给前端，也不提交到仓库。

## 已完成的实机验证（2026-09-07）

- 重新插入并唤醒后，设备处于 `work_mode=0`、ADB offline；现有身份认证后重新进入 ADB。
- SYNC `LIST` 与 `STAT` 实际读取设备目录、中文文件夹；`df` 实际读取容量。
- 新建 `/emmc/mindlink`，写入 4,142 字节测试内容，经 SYNC 读回逐字节一致；仅该测试文件已删除。
- 从网页创建“使用说明”目录，上传 `examples/A1-文件空间使用说明.txt`（878 字节），读回校验成功；使用说明保留在设备个人目录。
- 网页下载接口返回原始文件，不修改或删除 A1 原文件。

## 写入边界

- 浏览与下载限制在 `/emmc`。不开放 `/dev`、固件分区、任意 shell 或寄存器操作。
- 写入限制在 `/emmc/mindlink`。对录音目录与系统配置的写入请求会被拒绝。
- 不覆盖同名文件，包括 FAT 文件名大小写冲突。
- 每个文件先写同目录的随机 `.part` 临时文件，完整读回逐字节比较后再改成正式文件名，不增加内容摘要机制。
- 单文件最多 1 GiB，至少保留 1 GiB 可用空间供录音使用。1 GiB 上限已通过实机完整写入和逐字节读回验证，总计 683 秒；测试文件随后删除。测试使用流式数据，Python 跟踪的峰值分配约 0.7 MB。
- 普通上传失败会清理此次创建的临时文件；突然断电/拔线可能留下 `.a1-upload-*.part`，本版没有自动删除历史临时文件。
- 本版没有删除设备文件功能。上传任意文档并不表示 A1 自身能播放、执行或识别其内容。
- 文件名支持中英文、数字、空格、下划线、短横线、点和括号，末尾不能是空格或点。

所有 API 要求本机访问凭据；写请求还检查来源。录音与配置可能包含隐私，不要分享访问链接或设备身份文件。

## 当前限制

- USB 文件模式会停止正常录音并断开 BLE。未实现一键恢复普通模式或安全刷写。
- 录音下载是设备原始格式；普通录音和语音备忘录聚合容器暂不在此页面自动转码或播放，可使用父目录已有的离线音频导出工具。
- 界面不是 Windows 资源管理器虚拟盘，也没有修改固件提供 USB MSC。
- 本页上传是电脑 → A1。手机直接 USB OTG 连接仍需单独移植 Android USB 客户端。

## 开发

本机使用父目录已有 `.venv` 的 Python 与 `hidapi`、`cryptography`，HTTP 服务为 Python 标准库，不依赖云端。`server.py --adb <路径> --credentials <身份JSON> --port 8766` 可在其他安装路径启动。

前端依赖由 `pnpm-lock.yaml` 记录。安装使用 `pnpm install`，`pnpm-workspace.yaml` 只允许所需的 esbuild 安装脚本。可运行 `node ./node_modules/vite/bin/vite.js build` 生成 `dist/`；无需保持 Vite 开发服务常驻。

首次安装时遇到执行环境网络权限限制及包管理器的安装脚本策略；依赖下载完成后补充 esbuild 的显式构建许可。图标库该版本没有 FolderUser 导出，已改成与设计同风格的代码原生 SVG。最终构建使用本地 Vite CLI 成功。

冷启动验证还发现 PowerShell 7 的 HTTP 超时异常类型与旧版不同，导致端口尚未启动时脚本提前退出。已将异常捕获限定在 HTTP 探测步骤并兼容该差异；重新验证后台启动及原访问令牌复用成功。
